# 1차 도로 난이도 평가

Python 3.11 이상과 기존 Node 설치만 사용합니다. 추가 Python 패키지는 없습니다.

```powershell
npm run prepare:data  # integrated_roads 읽기 → difficulty_data/roads.sqlite
npm run dev           # SQLite 평가 API + Vite, http://localhost:5173
npm test
npm run build
npm run preview       # 빌드한 UI + 로컬 평가 API
```

DB가 없으면 dev/preview 시작 때 생성합니다. CSV 교체 후에는 prepare:data를 다시 실행하세요.
DB는 원본 CSV 여섯 개의 해시와 교차로 추정 설정을 기록합니다. 원본·통합 CSV는 수정하지 않습니다.
DB와 원본 CSV는 public/dist에 복사하지 않으며 Git에서도 제외합니다.

## 경로 입력

지도 방문지는 기존대로 입력할 수 있지만 길찾기는 구현하지 않았습니다.
일반 화면에서는 검증 입력을 제공하지 않습니다. 내부 테스트에서만 개발 도구를 켜거나 순서 있는 link_id 목록을 API에 전달합니다.
목록은 연결성과 기록 금지만 검사합니다. unknown 회전을 합법적이라고 확정하지 않습니다.

`POST /api/evaluate`: `{ "link_ids": ["1300004601", "1310022800"], "period": "11시~17시", "day_type": "weekday" }`

옵션 start_offset_m/end_offset_m은 첫/마지막 링크 시점부터의 거리(m)입니다.
생략하면 두 링크를 모두 통과합니다. 화면 선형은 부분 거리와 무관한 전체 링크 참고도입니다.
동일 링크 반복은 순서를 유지합니다. 주말은 구조 평가만 하며 교통은 null입니다.

## 임시 기준 변경

config.json에서 산식 상수·임계값·교통 가중을 변경합니다. version도 함께 변경하세요.
연속 상황과 다른 기본식을 바꿀 때는 evaluate.py를 수정하고 npm test를 실행합니다.
교차로 거리·갈래 각도 설정 3개를 바꾸면 prepare:data가 필요하며 API가 재생성을 안내합니다.

- 감소: 감소 차로 수/진입 차로 수 × 100. 교차로 통과 내 선택 전환의 최댓값.
- 회전: 내부 전환을 묶은 진입→최종 진출 각도의 절댓값을 설정의 직진/포화 각도 사이에서 0~100으로 변환.
- 교차로: 자동 추정 갈래 수가 2를 넘는 정도를 설정의 최대 갈래 수까지 변환.
- 합류·분기: 원천 위상 후보에 설정 점수. 실제 시설 확정이 아님.
- 교통: 혼잡빈도/시간강도 가중 평균에 동일 그룹·2025 평일 기간별 속도의 상대 저하를 보조 반영.
  낮은 속도만으로 점수를 만들지 않습니다. 혼잡은 평일 전체 값이며 시간대별 값이 아닙니다.
- 구조·연속 점수에 대응하는 진입 도로의 교통 지표로 제한적 가산. 교통 누락은 보정 미평가로 남기고 원점수를 보존.
- 연속: 서로 다른 추정 교차로 사이의 블록 안에서 상황 종류·블록 길이·사건 간 거리를 함께 사용.
  한 쌍이 여러 종류에 해당해도 한 번만 점수화. 실제 차로 변경 횟수는 미평가.
- 세 대분류는 평가된 세부 항목 중 최고값. null은 0이 아니며 부분 수록 상태·길이 확보율을 별도 제공.

## 선택적 LLM

기본 해설은 실제 평가 근거를 이용한 규칙 기반 문장입니다. LLM 결과라고 표시하지 않습니다.
.env.server.example을 루트의 .env.server로 복사하고 OPENAI_API_KEY, OPENAI_MODEL,
ENABLE_LLM=true를 설정한 뒤 dev를 재시작하세요. 키는 VITE_ 변수에 넣지 마세요.
화면에서 ‘서버 LLM 해설 요청’을 누를 때만 실제 요청하므로 공급자의 이용 요금이 적용될 수 있습니다.

서버는 OpenAI Responses API를 사용하고 store=false로 요청합니다.
전체 CSV·선형·방문지 입력은 보내지 않고 상위 평가 사실·위치·점수·수록률만 전달합니다.
LLM은 중요 근거 ID와 승인된 준비사항 ID만 선택합니다. 서버는 최고점 포함 여부·근거 ID를 검증하고
원문 사실을 조합하여 위치·이유·준비사항을 표시합니다. 자유 생성으로 없는 특성을 추가하지 않습니다.
API 오류·근거 검증 실패는 규칙 기반으로 대체하며 화면에 이유를 표시합니다.
실제 호출에는 별도 API 이용 권한·데이터 전달 조건 확인이 필요합니다. 테스트의 LLM 응답은 네트워크 없는 모의 응답입니다.

공식 연결 명세: https://developers.openai.com/api/reference/resources/responses/methods/create

교차로·갈래·블록은 XY와 연결 기반 추정입니다. 입체·근접 별개 교차로를 오병합할 수 있고,
난이도는 초보운전자 체감 검증 전 임시 지표입니다. 로컬 개발 서버이며 인터넷 공개 배포·사용자 인증은 포함하지 않습니다.

## 화면 개선 이후
일반 화면에서는 고정 검증 경로와 도로 ID 입력을 표시하지 않습니다. 현재는 선택 장소를 자체 방향 도로망에 연결하여 실험 경로를 탐색·분석합니다. 통행 허용을 검증한 내비게이션 경로는 아닙니다.
내부 화면 검증이 필요할 때만 프로세스 환경변수 VITE_ENABLE_DEV_TOOLS=true로 npm run dev를 시작합니다. 기본값은 false이며 production build에서는 true여도 개발 입력 모듈을 포함하지 않습니다.
결과의 상황별 가로 막대는 같은 세부 항목의 최고값만 표시합니다. src/data/presentation.js는 표시용 묶음·쉬운 설명만 담당하며 evaluate.py와 config.json 산식은 변경하지 않았습니다.

카카오 지도 기본 주소는 http://localhost:5173 입니다. 127.0.0.1로 문서를 열면 localhost로 이동합니다.
키가 같아도 SDK 등록 도메인이 다르면 로딩에 실패합니다. 빌드 미리보기의 http://localhost:4173은 별도 등록이 필요할 수 있습니다.
기존 .env.local 키는 변경하지 않았습니다.


## 자체 길찾기
`npm run prepare:data` 후 `npm run dev`. 이전 DB는 시작 시 길찾기 속성 테이블이 없으면 재생성합니다.
`POST /api/route`: `places: [{name,lon,lat}, ...]` 2~6개, `period`, `day_type`.
응답은 기존 평가 결과에 `routing`(주행 순서 ID·끝점 통과 위치·장소 연결·거리·탐색 시간·경고)과 잘라낸 `route_geometry`를 포함합니다.
기존 `/api/explain`에는 `routing.evaluation_request`를 그대로 전달합니다. 점수 산식·가중치와 LLM 연결부는 유지했습니다.

방향 링크 상태 다익스트라, 거리 + 장소 연결 거리의 4배를 비용으로 사용합니다. 장소당 가까운 6개 후보(최단 연결거리+25m 이내, 최대150m), 교차로 내부 링크 제외. 차량 통행/양수 중량·높이 제한 필터, 기록된 금지 전환 제외, 즉시 역행 및 150도 이상 유턴 후보 제외. 같은 교차로 내부 이동의 누적 진입·진출 방향도 확인합니다. 시작·끝 링크의 부분 길이를 평가에 전달합니다.
경유 순서와 같은 방향 도로의 같은 통과 위치를 유지합니다. 각 경유지까지 순차 최적화하므로 전체 경유 경로의 전역 최단 경로는 보장하지 않습니다. 경유지의 다른 연결 후보를 선택하면 가능한 경로도 현재 순차 선택에서는 실패할 수 있습니다. 정상 회차·급커브도 보수적 유턴 필터로 제외될 수 있습니다.

차량 제한 코드의 원천 설명서는 미해석 상태입니다. 과거 공식 코드표(https://www.codil.or.kr/filebank/moctroadguide/LS/CIKCLS121170/CIKCLS121170.pdf)의 승용차1/기타6/알 수 없는 코드를 제외하는 실험 필터이며 현재 자료와의 완전한 의미 일치는 검증되지 않았습니다. 중량 kg·높이 cm는 통합 설명서 기준, 0은 제한 없음이 확정된 값으로 해석하지 않습니다. 기본 승용차 2000kg·180cm이며 API에서 `vehicle:{weight_kg,height_cm}` 지정 가능. 모든 결과 `legal_access_confirmed:false`.
회전 허용·시간제한·진입금지 누락, 실제 차량 출입구·도로 높이·주차장 연결이 검증되지 않았습니다. 일방통행은 주어진 from→to 방향을 따르지만 원천 방향의 현행 법적 정확성까지 보장하지 않습니다. 결과를 운전 안내로 사용하지 않습니다. 실서비스 자동차 길찾기는 검증된 외부 API로 전환하는 편이 적합하며 이번에는 연결하지 않았습니다.

검증: `npm test`(기존19개 + 길찾기7개), `npm run build`. 실제 도로 연결/금지/차량 필터/부분 링크/경유 순서/평가 변화/API 응답을 검사합니다. 측정치는 `difficulty_data/routing_validation.json`에 기록됩니다. 테스트 좌표는 장소 입구를 확정한 좌표가 아니며 브라우저의 카카오 장소 좌표와 다릅니다.
브라우저: 부산역→해운대, 광안리 경유, 시청→서면 장소 검색·경로 선·그래프·규칙 해설 확인. 비교 사이트 카카오맵에서 부산역→해운대 거리우선14.0km, 내비추천16.8km 확인(조회 당시 값). 자체13.814km는 출입구/접근 구간 미포함이므로 정확한 동일 조건 비교나 합법성 검증으로 간주하지 않습니다. 실제 LLM 호출은 수행하지 않았습니다.


## 점수 과포화 완화 (prototype-2-softscale)
현재 작업 경로: C:/Users/Home/Documents/ChatGPT/소공팀플.
구조/연속 상황의 혼잡 가중 후 원시값과 교통 지표를 `100*x/(x+60)`으로 완만하게 변환합니다. 교통은 먼저 한 번 변환하고 구조·연속 상황의 추가 부담에 활용하며, 화면 출력 시 교통 점수를 중복 변환하지 않습니다. 원래의 100점 절단에서 생기던 동점을 줄이기 위해 회전·갈래 수의 원시값 절단도 제거했습니다. 0과 미평가, 대분류 최고값 집계는 유지합니다.
`config.json`의 `score_half_saturation`을 높이면 더 낮게 평가됩니다. 기본60은 임시 표시 척도이며 운전자 실측으로 검증한 객관적 난이도가 아닙니다. 교통 혼잡 원값100%도 난이도100점과 같은 뜻이 아닙니다. `base_score`는 변환 전 원시값, `unmodified_score`는 혼잡 추가 부담 전 표시 점수입니다.
9개 기존 검증 경로의 변경 전/후 비교: difficulty_data/score_validation.json. 도로 원본과 교차로 묶음 규칙은 변경하지 않았습니다.


## Gemini 해설 연결
현재 .env.server는 `LLM_PROVIDER=gemini`, `GEMINI_API_KEY`, `GEMINI_MODEL=gemini-3.5-flash-lite`, `ENABLE_LLM=true`를 사용합니다. 기존 키 값은 비공개 파일 안에서 변수 이름만 변경했으며 프론트엔드로 전달하지 않습니다. 모델 표시 이름 대신 공식 models 조회에서 확인한 모델 ID를 설정했습니다.
설정 후 `npm run dev`를 재시작합니다. 경로 분석 완료 시 Gemini가 중요 근거·준비사항을 선택하고 서버가 실제 근거를 검증해 해설을 구성합니다. 화면의 AI 해설 요청 버튼으로 다시 생성할 수도 있습니다. 점수 계산과 원본 CSV는 LLM에 맡기지 않습니다. 최고 점수 근거를 첫 항목으로 선택하도록 명시하며 없는 근거/부적합 응답/호출 실패는 규칙 안내로 대체합니다. 브라우저 키 노출을 막기 위해 Gemini 호출은 Python 서버에서만 수행하고 키는 HTTP 헤더로 전송합니다.
실제 Gemini 호출에서 `llm_grounded` 응답을 확인했습니다. 기존 '실제 호출 미수행' 설명은 이전 버전 검증 기록입니다.
공식 명세: https://aistudio.google.com/api-reference/models 및 https://aistudio.google.com/docs/structured-output .
